# 第9章：打包发布与依赖管理

> **学习目标**：理解 Maven 多模块项目的打包策略、Spring Boot Starter 模式、以及如何发布为可复用的依赖。

---

## 9.1 Maven 多模块结构

```
openclaw-spring-boot-starter/         ← 父 POM（聚合器）
├── pom.xml                           ← 定义公共依赖版本
│
├── openclaw-runtime-api/             ← 接口层
│   └── pom.xml
├── openclaw-runtime-client/          ← 通信层
│   └── pom.xml
├── openclaw-runtime-event/           ← 事件层
│   └── pom.xml
├── openclaw-runtime-session/         ← 会话层
│   └── pom.xml
├── openclaw-runtime-skill/           ← 技能层
│   └── pom.xml
├── openclaw-runtime-converter/       ← 转换层
│   └── pom.xml
├── openclaw-runtime-autoconfigure/   ← 自动配置层
│   └── pom.xml
├── openclaw-runtime-starter/         ← Starter（纯 POM）
│   └── pom.xml
└── samples/                          ← 示例（不发布）
    ├── sample-runtime/
    └── sample-skill-provider/
```

## 9.2 父 POM 设计

父 POM 统一管理依赖版本，子模块不需要重复声明：

```xml
<project>
    <groupId>io.openclaw</groupId>
    <artifactId>openclaw-spring-boot-starter-parent</artifactId>
    <version>1.0.0-SNAPSHOT</version>
    <packaging>pom</packaging>

    <modules>
        <module>openclaw-runtime-api</module>
        <module>openclaw-runtime-client</module>
        <module>openclaw-runtime-event</module>
        <module>openclaw-runtime-session</module>
        <module>openclaw-runtime-skill</module>
        <module>openclaw-runtime-converter</module>
        <module>openclaw-runtime-autoconfigure</module>
        <module>openclaw-runtime-starter</module>
        <module>samples/sample-runtime</module>
        <module>samples/sample-skill-provider</module>
    </modules>

    <properties>
        <java.version>17</java.version>
        <spring-boot.version>3.3.6</spring-boot.version>
        <lombok.version>1.18.34</lombok.version>
        <jackson.version>2.17.2</jackson.version>
    </properties>

    <dependencyManagement>
        <dependencies>
            <!-- Spring Boot BOM -->
            <dependency>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-dependencies</artifactId>
                <version>${spring-boot.version}</version>
                <type>pom</type>
                <scope>import</scope>
            </dependency>

            <!-- 内部模块 -->
            <dependency>
                <groupId>io.openclaw</groupId>
                <artifactId>openclaw-runtime-api</artifactId>
                <version>${project.version}</version>
            </dependency>
            <!-- ... 其他内部模块 ... -->
        </dependencies>
    </dependencyManagement>
</project>
```

## 9.3 Starter 模块（核心）

`openclaw-runtime-starter` 是用户最终依赖的模块。它**没有任何源码**，只做依赖聚合：

```xml
<project>
    <artifactId>openclaw-runtime-starter</artifactId>
    <description>OpenClaw Runtime Spring Boot Starter</description>

    <dependencies>
        <!-- 引入自动配置 -->
        <dependency>
            <groupId>io.openclaw</groupId>
            <artifactId>openclaw-runtime-autoconfigure</artifactId>
        </dependency>

        <!-- 传递依赖（autoconfigure 已声明） -->
        <!-- api, client, event, session, skill, converter -->
        <!-- 都会自动引入 -->
    </dependencies>
</project>
```

### 为什么需要单独的 Starter 模块？

这是 Spring Boot 的标准模式：

```
用户项目
  └─ 依赖 openclaw-runtime-starter
       └─ 依赖 openclaw-runtime-autoconfigure
            ├─ 依赖 openclaw-runtime-api
            ├─ 依赖 openclaw-runtime-client
            ├─ 依赖 openclaw-runtime-skill
            └─ ...
```

| 好处 | 说明 |
|------|------|
| 简化依赖 | 用户只需写一行 `<artifactId>` |
| 版本一致 | 所有内部模块版本由 Starter 锁定 |
| 可选排除 | 高级用户可以排除某些模块 |

## 9.4 子模块 POM 示例

以 `openclaw-runtime-client` 为例：

```xml
<project>
    <parent>
        <groupId>io.openclaw</groupId>
        <artifactId>openclaw-spring-boot-starter-parent</artifactId>
        <version>1.0.0-SNAPSHOT</version>
    </parent>

    <artifactId>openclaw-runtime-client</artifactId>

    <dependencies>
        <!-- 内部依赖 -->
        <dependency>
            <groupId>io.openclaw</groupId>
            <artifactId>openclaw-runtime-api</artifactId>
        </dependency>

        <!-- Spring WebFlux (WebClient + ReactorNettyWS) -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-webflux</artifactId>
        </dependency>

        <!-- Jackson -->
        <dependency>
            <groupId>com.fasterxml.jackson.core</groupId>
            <artifactId>jackson-databind</artifactId>
        </dependency>

        <!-- 测试 -->
        <dependency>
            <groupId>io.projectreactor</groupId>
            <artifactId>reactor-test</artifactId>
            <scope>test</scope>
        </dependency>
    </dependencies>
</project>
```

## 9.5 构建命令

```bash
# 完整构建（含测试）
mvn clean install

# 跳过测试构建
mvn clean install -DskipTests

# 只构建某个模块
mvn clean install -pl openclaw-runtime-client

# 构建某个模块及其依赖
mvn clean install -pl openclaw-runtime-client -am

# 运行测试
mvn test

# 运行单个测试类
mvn test -Dtest=ChatClientTest -pl openclaw-runtime-client
```

## 9.6 发布到 Maven 仓库

### 本地安装

```bash
mvn clean install
# 安装到 ~/.m2/repository/io/openclaw/
```

### 发布到远程仓库

配置 `distributionManagement`：

```xml
<distributionManagement>
    <repository>
        <id>releases</id>
        <url>https://maven.your-company.com/releases</url>
    </repository>
    <snapshotRepository>
        <id>snapshots</id>
        <url>https://maven.your-company.com/snapshots</url>
    </snapshotRepository>
</distributionManagement>
```

```bash
# 发布
mvn clean deploy -DskipTests
```

## 9.7 用户使用方式

### 添加依赖

```xml
<dependency>
    <groupId>io.openclaw</groupId>
    <artifactId>openclaw-runtime-starter</artifactId>
    <version>1.0.0</version>
</dependency>
```

### 配置

```yaml
openclaw:
  endpoint: http://gateway:13015/path
  token: your-auth-token
```

### 使用

```java
@Service
public class MyService {
    @Autowired
    private OpenClawRuntime runtime;

    public String chat(String message) {
        ChatResponse response = runtime.sendMessage(message);
        return response.getContent();
    }
}
```

## 9.8 版本管理策略

| 环境 | 版本格式 | 示例 |
|------|---------|------|
| 开发 | `X.Y.Z-SNAPSHOT` | `1.0.0-SNAPSHOT` |
| 发布 | `X.Y.Z` | `1.0.0` |
| 预发布 | `X.Y.Z-RC.N` | `1.0.0-RC.1` |

### 语义化版本

```
MAJOR.MINOR.PATCH

1.0.0 → 1.0.1  ← Bug 修复（向后兼容）
1.0.0 → 1.1.0  ← 新功能（向后兼容）
1.0.0 → 2.0.0  ← 破坏性变更
```

## 9.9 依赖排除示例

如果用户想替换某个模块的实现：

```xml
<dependency>
    <groupId>io.openclaw</groupId>
    <artifactId>openclaw-runtime-starter</artifactId>
    <version>1.0.0</version>
    <exclusions>
        <!-- 排除默认的 WebSocket 实现 -->
        <exclusion>
            <groupId>io.openclaw</groupId>
            <artifactId>openclaw-runtime-client</artifactId>
        </exclusion>
    </exclusions>
</dependency>

<!-- 引入自定义实现 -->
<dependency>
    <groupId>com.mycompany</groupId>
    <artifactId>custom-openclaw-client</artifactId>
    <version>1.0.0</version>
</dependency>
```

## 9.10 小结

| 知识点 | 要点 |
|--------|------|
| 多模块结构 | 每个模块有明确职责，通过依赖图连接 |
| Starter 模式 | 纯 POM 聚合器，用户只需依赖一个模块 |
| 版本管理 | 父 POM 统一锁定，语义化版本号 |
| 构建命令 | `mvn clean install` 全量构建 |
| 发布 | `mvn deploy` 到远程仓库 |
| 使用 | 一行依赖 + YAML 配置即可接入 |
