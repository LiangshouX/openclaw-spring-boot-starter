# 常见问题 (FAQ)

## 1. 发布相关

### Q: deploy 时报 401 Unauthorized

**原因**：Sonatype Token 无效或过期。

**解决**：
1. 登录 https://central.sonatype.com/
2. 重新生成 User Token
3. 更新 GitHub Secrets 或本地 `~/.m2/settings.xml`

### Q: deploy 时报 403 Forbidden

**原因**：Namespace 未验证或没有发布权限。

**解决**：
1. 确认 Sonatype Central Portal 中 namespace 已验证通过
2. 确认使用的 groupId 在已验证的 namespace 下

### Q: GPG 签名失败

**可能原因**：
- GPG 密钥未导入到 GitHub Actions 环境
- passphrase 不正确
- 密钥服务器未同步公钥

**解决**：
1. 确认 `GPG_PRIVATE_KEY` Secret 包含完整的私钥（包括首尾标记行）
2. 确认 `GPG_PASSPHRASE` 与生成密钥时设置的密码一致
3. 确认公钥已上传：
   ```bash
   gpg --keyserver keyserver.ubuntu.com --send-keys YOUR_KEY_ID
   ```

### Q: Staging 仓库校验失败

**可能原因**：
- 缺少 sources.jar 或 javadoc.jar
- POM 缺少必需元数据（name, description, url, licenses, developers, scm）
- 存在未签名的 artifact

**解决**：
1. 确认使用了 `-Prelease` profile
2. 检查根 pom.xml 中的元数据是否完整
3. 查看 Sonatype Central Portal 的错误详情

### Q: 发布后在 Maven Central 搜不到

**原因**：同步延迟。

**说明**：发布成功后，artifact 需要 10-30 分钟（最长可能 2 小时）才会出现在 Maven Central 搜索索引和镜像仓库中。

可以直接访问以下 URL 验证文件是否已上传：
```
https://repo1.maven.org/maven2/io/openclaw/runtime/openclaw-runtime-starter/
```

## 2. 构建相关

### Q: javadoc 生成失败

**原因**：代码中的 Javadoc 注释有语法错误，或者 doclint 过于严格。

**解决**：已在 release profile 中配置 `<doclint>none</doclint>`。如果仍有问题，检查是否有严重的语法错误。

### Q: flatten-maven-plugin 报错

**原因**：插件版本不兼容。

**解决**：确认使用 1.6.0+ 版本。如果仍有问题，可以尝试清理后重新构建：
```bash
mvn clean
mvn clean install
```

### Q: samples 模块 deploy 失败

**说明**：samples 模块已配置 `<maven.deploy.skip>true</maven.deploy.skip>`，不应参与 deploy。

如果仍然报错，确认 samples 模块的 pom.xml 中包含该属性。

## 3. GitHub Actions 相关

### Q: workflow_dispatch 看不到输入参数

**解决**：确保在 GitHub 仓库页面的 Actions 标签页中选择 **Run workflow** 按钮后，会弹出参数输入框。如果看不到，检查 yml 文件中的 `inputs` 定义是否正确。

### Q: Git push 失败 (permission denied)

**原因**：GitHub Actions 默认使用 `GITHUB_TOKEN`，权限有限。

**解决**：
1. 确认 workflow 文件中设置了 `permissions: contents: write`
2. 如果仍然失败，检查仓库的 Actions 权限设置：Settings → Actions → General → Workflow permissions → 选择 **Read and write permissions**

### Q: Maven 缓存未命中

**说明**：`actions/setup-java` 的 `cache: maven` 功能会缓存 `~/.m2/repository`。首次运行或 `pom.xml` 变更后缓存可能失效，这是正常的。

## 4. GPG 相关

### Q: 如何查看本地 GPG 密钥列表？

```bash
gpg --list-keys --keyid-format SHORT
gpg --list-secret-keys --keyid-format SHORT
```

### Q: 如何删除本地 GPG 密钥？

```bash
# 先删除私钥
gpg --delete-secret-keys YOUR_KEY_ID

# 再删除公钥
gpg --delete-keys YOUR_KEY_ID
```

### Q: 如何从密钥服务器导入公钥？

```bash
gpg --keyserver keyserver.ubuntu.com --recv-keys YOUR_KEY_ID
```

## 5. 其他

### Q: 如何回滚已发布的版本？

**Maven Central 的政策是不允许删除已发布的 artifact。**

如果发现已发布版本有严重 bug：
1. 发布一个修复后的新版本（递增 patch 版本号）
2. 在项目的 README 和 Changelog 中标注旧版本存在问题
3. 通知用户升级到新版本

### Q: 可以同时维护多个版本线吗？

可以。例如同时维护 `0.0.x` 和 `0.1.x`：
```bash
# 从 v0.0.1 tag 创建维护分支
git checkout -b maint/0.0.x v0.0.1

# 在该分支上进行修复并发布 0.0.2
```

但建议在项目早期阶段只维护一个版本线。
